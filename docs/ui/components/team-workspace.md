# Team 工作区

沿用 [DESIGN.md](../../../DESIGN.md) 的主题规则、原生队员列表与详情分栏。主侧栏显示“团队 / Team”；
新增与名册添加统一为“添加 / Add”。团队列表支持收起和调宽；Mobile 列表/详情逐级返回。
空态沿用 MCP 引导，提供添加空白团队和显式从现有默认配置创建。

详情按名称、可选团队指引、队员行列表排列。指引默认两行预览，添加/编辑后展开；计数 10000 字，
超限保存报错，不静默截断。指引使用现有 workspace-surface-subtle 底色、10px 圆角，
与名称和名册同宽；名册用细边框和圆角收拢，hover/focus 行使用同一语义底色。所有配色只用语义 Token，
左侧列表沿用原样式。窄屏行操作换行，减少动态效果时取消行底色过渡。
名册通过多选下拉添加；超过八位候选提供搜索。
行操作以图标加文字平铺，hover/focus 显示 Make lead 与 Remove，触屏常驻；队长标记留在名字旁。
不可用成员保持可见，可移除但不可设为新队长。

新建、编辑显式保存；离页、切换团队、复制或开始新对话时保护未保存草稿。
仅在没有团队与编辑草稿时显示整页加载态；后台刷新保留编辑表单和保存/离页/删除确认框，
在保存栏显示非阻塞的加载状态，用户仍可编辑或取消离页。
“保存并继续”开始新对话时直接采用保存回执的 Team 快照，不等待或重新依赖团队列表刷新。
放弃草稿或再次选择当前团队时，同 ID 的旧列表快照不能覆盖已确认的新版本；显式重新载入仍可接受
较新版本，删除后的列表回退继续有效。旧列表版本不显示“在其他地方更改”提示。
新对话与复制在发起时固定 Team ID；确认后只接受同 ID 的快照。放弃更改时，列表可以回退选择
其他团队，但待执行动作必须取消并提示重新选择，不能随列表选择转向另一 Team。
重复提交使用原命令核对回执；CAS 冲突提供重新载入。复制/删除菜单保持横向紧凑文案；删除先确认。
六人、十二人列表独立滚动，保存栏可见。UI 不显示 Bootstrap 注入或旧会话更新机制提示。

通用设置的默认配置只选择 Team 或 Custom，无管理团队链接。Custom 可编辑成员与队长；选择 Team
只展示精简摘要，不覆盖 Custom。团队删除时关闭一键创建并回到保留的 Custom。
新对话选择器 Custom 在首项：Custom 保留原成员/队长控件，Team 只读显示头像、人数与队长。
切换两种来源保留本次 Custom 草稿；无另存为团队。沿用可选名称和创建成功后保存一键配置的行为。
初始团队列表晚到时只补齐尚未加载的 Team，不重置已编辑名称、工作区或主动切换的 Custom；
已经选定的 Team 快照不随列表刷新替换，后续外部修改仍由创建时的版本校验处理。
Custom 的一键创建与普通弹窗不等待团队列表；列表加载或失败只在选择器旁呈现，失败可重试，
Custom 仍可选择并创建。选定 Team 的一键创建必须取得有效快照，读取失败进入弹窗，不能静默改用 Custom。
Web 团队列表只随团队变更或连接重新同步刷新；其他业务失效事件不会让团队选择器进入加载态。
未取得快照的 Team 不从失败或正在刷新的旧列表初始化；保存回执与已选定快照继续保留。
共享偏好回执内容未变时保留原 state，避免同一失效观察因回执对象变化而反复提交；刷新中不使用旧名册判断失效。
失效请求期间收到的新观察合并为一次补查；请求完成后使用最新偏好与名册重新判断。
没有新观察时不重试；最新名册已恢复可用时不提交失效请求。
团队主动作、队员选中框及团队选中标记使用当前主题的 `conversation-action` 系列 token，
包括挂载到 Portal 的选择菜单与确认弹窗。日间深色、夜间浅色，其他主题沿用各自的 action 色；
删除保留 danger 语义，主侧栏“新对话”保留普通导航样式。

记忆入口移入“设置 → 应用”，保留待审核计数；主侧栏设置旁仅在有待审核项时出现记忆快捷入口。
数据与上下文语义由 [Team Templates v2](../../contracts/team-templates-v2.md)
和 [Bootstrap v6](../../contracts/native-session-bootstrap-v6.md)拥有。

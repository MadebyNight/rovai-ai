# Input History v1

公共 Thread 与私有 Single Chat 共用同步导航。User 首次按满足条件的 ↑ 时，从现有消息数据
提取本轮可回填内容；历史不拥有查询、分页、跨会话缓存、发送回执或草稿存储。

## 数据来源与内容

- 公共输入使用当前 `visibleThreadMessages`；复用现有正式、本地和已加载导航窗口的合并、去重及顺序。
  只提取 `authorType: user`、`authorId: local_user` 且未撤回的可回填消息。
- 单聊使用当前 `currentSnapshot.messages` 的当前 User 正式消息，后接
  `currentSnapshot.pendingInputs.items`。分别沿用消息顺序和队列顺序，从末尾向前浏览。
  Pending 列表已有 queued / needs_repair；不补查 cancelled，不建立发布前后的身份或提交时间映射。
- 公共内容转换为独立的 `ComposerDocument`，仅保留 Text、Member、All Members、Skill Atom。
  外部引用段、Current User Mention、附件、回复关系和执行参数不复制。
- 原始结构化内容为空才使用保存的 `body`；原内容过滤后为空则跳过，不能回退正文复活引用文字。
- 单聊提取正文字符串。纯附件、空白正文跳过；含 Atom 的公共输入仍可回填。
  `trim()` 只用于判断空白，回填保留缩进、换行及原文，不改变现有单聊发送的 trim 规则。
- 相同正文的不同提交保留。不为历史增加 ID、确认门槛、发送状态或新的消息去重。

范围完全由已有消息数据决定，不保证覆盖尚未加载的记录或已加载记录连续。
输入历史不能扩大聊天窗口读取量、触发消息分页或全量加载，也没有独立数据库接口。
当前单聊快照返回全部正式消息是消息模块的现状，历史功能不拥有这一加载承诺。

## 本轮浏览

共享导航仅保存可回填内容数组、当前下标、原草稿与选区快照：

- 首次符合条件的 ↑ 同步提取一次。无记录则不进入浏览、不消费按键。
- 数组为独立内容快照，不保留整份可变消息、会话快照、Agent 输出或附件。
- 普通消息刷新、新提交、加载旧消息、pending 发布/取消、撤回均不修改本轮数组和下标。
- 到达最旧条目后停止，不发出请求。下一轮首次 ↑ 再提取最新的现有数据。
- 编辑、发送、显式替换草稿、退出或切换目标后释放本轮数组。公共按 Thread、单聊按 Conversation 隔离。
- 取数回调始终读取当前目标的最新数据；回调或消息对象引用变化不重建本轮导航。

没有预加载、每页容量、离开裁剪、LRU、请求合并或迟到响应处理。
首次提取的遍历和复制成本随现有消息量增长，不创建后台任务。

## 草稿、预览与键盘

草稿继续由现有存储负责，不作为历史条目。公共输入保留结构化 EditorState；
单聊保留原正文与 selection，预览期间不把历史内容自动保存为原草稿。

| 操作 | 行为 |
| --- | --- |
| 无选区/修饰键、文档绝对起点的 `↑` | 更早一条，回填后光标置于起点 |
| 浏览中、无选区/修饰键、文档绝对终点的 `↓` | 较新一条，回填后光标置于终点 |
| `↓` 越过最新条目 | 恢复原草稿及 selection，结束浏览 |
| 浏览中、无选区/修饰键的 `Esc` | 恢复原草稿并消费事件，单聊不同时关闭 |
| 公共输入预览中执行 Undo / Redo | 结束浏览，原草稿恢复提交完成后，再由现有撤销栈执行该命令 |
| 编辑正文或显式修改输入路由/引用 | 接管为普通草稿，结束浏览 |
| 发送预览 | 捕获有效内容，接管到现有协调器，再 flush/发送 |
| 显式替换草稿，如 pending 移回或外部命令 | 结束浏览并采用新草稿，即使新正文恰好等于原稿 |
| 离开或切换会话 | 清理本轮导航，保留原会话草稿 |

候选/链接菜单及 IME 优先。有选区、修饰键或不在边界时保留原编辑行为；不测量视觉行。
非浏览中的 Down 不接管，只有实际移动或恢复草稿才消费事件。

预览驱动显示、发送/停止按钮、接收者提示和发送资格。自动保存、重试、普通 leave flush 仍处理原稿。
用户编辑/发送才接管；发送明确捕获有效内容，不依赖更新状态后的旧闭包。
附件、quotes、reply 等字段继续由现有流程管理；不建立第二份持久草稿。
浏览、移动光标、Atom 展示刷新与退出不把预览条目写入 Undo；退出后仍使用原稿的撤销/重做记录。
公共输入在预览中直接撤销/重做时，先消费命令，等待恢复提交完成再转交一次，不能恢复尚未提交就放行。
即使对应撤销/重做栈为空，也结束预览并保留原稿。单聊恢复时，正文未变化则不重复保存原稿。

## 消息变化

新提交是否可用跟随现有消息数据与发送后的刷新流程，不通过成功回执单独记录历史。
尚未出现在已有数据中的输入可以暂时翻不到，↑ 不补查；浏览中到达的新输入在下一轮纳入。
Pending 发布后下一轮读取正式消息，取消且离开快照的 pending 不额外找回。
不新增撤回监听、逐条核对或缓存清理；本轮已经提取的正文可保留至结束，下一轮依据最新数据。
主动再次发送仍是一次新的提交，不恢复原消息。

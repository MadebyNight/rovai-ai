# File Preview v22

继承 [v21](file-preview-v21.md) 的来源、读取、HTML 隔离与诊断合同。本版替代早期“外部变化只标记更新”
以及“热命中一律不重读”的行为：普通文件默认自动刷新，仍复用已有候选读取、Viewer 和资源所有者。
不增加 wire、依赖、持久化配置或设置；File Change、Activity、Execution 不进入文件刷新调度。

## 自动刷新与重新显示

- Desktop 沿用 root watcher，Web 沿用原有文件变化检查。事件更新已有
  `hasExternalUpdate` 与 `externalUpdateVersion`；只有当前 Thread、展开预览中的活动文件可以发起自动读取。
- 同一标签的变化通知以 300ms 末尾防抖合并；这是通知后的延迟，不包含 Web 原有检查周期。
  实际发起读取前及补刷时重新检查当前可见性。后台标签、收起的预览和其他 Thread 只保留更新标记。
- 激活标签、切回 Thread、展开预览、再次打开已有文件、关闭活动标签后显示下一项，统一检查：
  已加载且有更新时刷新；有缓存但句柄已回收时恢复候选；冷标签沿现有恢复路径加载；
  仍持有能力且未变化的热内容继续复用。
- 首次加载期间收到的更新，在加载完成后检查。首次加载、手动刷新、自动刷新和 HTML 候选等待
  共用已有加载/刷新状态，同一标签不并发刷新。刷新中收到的通知只推进更新版本，
  当前请求成功后仍有更新且可见时再合并补刷，不逐条排队。
- 切走前已经发出的读取继续归原 Thread/session/tab/requestGeneration；不抢焦点、不切换活动标签，
  不因完成或通知提升 LRU。尚未发出的自动任务取消，更新标记保留。

## 候选、失败与释放

继续先读取候选，成功后替换，显示提交后释放旧内容、句柄和资源。读取失败或文件被删除时，
保留旧内容并展示已有刷新错误与重试入口。失败后重复通知只标记更新；
只有明确重试、再次打开或重新显示该文件才允许再尝试一次，重复渲染与普通状态更新不算重新显示。

HTML 候选仍要求根文档 `loaded` 且页面通道连接有效；站点 URL 返回不代表刷新结束。
整页替换可以重置作者表单及脚本状态，滚动继续沿用已有处理。
仅打开文件自身的变化进入刷新；不建立 CSS、JS、图片等关联资源的依赖追踪。

关闭标签、内容/句柄淘汰、session 换代或释放时清理对应计时器与调度记录，
沿既有 generation 检查丢弃迟到响应并释放候选。容量限制与旧可见内容保护继续有效。

## 分页阅读位置

Renderer 的窗口内阅读快照记录当前可见行号。刷新或冷恢复时，通过现有 `resolveLine`、`readPage`
在新版本定位，重新建立分页位置与缓存，不复用旧版本的字节偏移。请求行超出缩短后的文件时，
回落到最后有效行；空文件保持可读空内容。行号恢复不进行 diff 对齐或语义锚定，不新增全文/行索引服务。

## 验收

1. 当前文件：文本、Markdown、代码、图片、HTML 自动显示新内容；大文本非首页刷新按行恢复，缩短时有效回落。
2. 后台切回：后台无读取，所有重新显示入口按需更新；包含缓存仍在但句柄回收，以及防抖期间切走。
3. 连续修改：末尾防抖、首次读取期间修改、手动与自动竞争、HTML 等待时再修改，最终收敛且无并发刷新。
4. 失败与关闭：失败保留旧内容，重复通知不重试，明确入口可重试；关闭、淘汰、换代清理任务和迟到资源。

共享调度验证一份，Desktop 和 Web 各验证通知与读取接线。界面继续使用既有刷新中、错误和重试展示。

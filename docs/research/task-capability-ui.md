# 会话任务开关：界面设计稿

本稿承接 [Task 能力开关 R4](task-capability-switch.md)，覆盖通用设置、会话、提醒和快捷键四个页面。
开关放在 **设置 → 通用 → 会话 → 世界地图下方**，默认关闭。关闭后移除会话的 Task 功能及任务提醒组，
保留现有布局、消息、执行、队员、单聊、使命和定时任务。

这是设计提案和可交互原型，尚未改变产品代码、当前 UI 合同或 Core 行为。
设计检查按 `/ui-ux-pro-max` 的现有系统增量流程进行，以仓库 [DESIGN](../../DESIGN.md)、
[UI 规范](../ui/README.md)和当前组件为准。原型中的会话、配置、任务与执行状态使用合成示例数据。

## 1. 如何审阅

交付文件 `task-capability-review.html` 内嵌 CSS、脚本、图标和内置头像，可独立打开。
上方控制栏、下方评审注释不属于拟上线的产品界面。

- 页面：通用设置 / 会话 / 提醒 / 快捷键。
- 状态：当前界面 / 关闭·默认 / 开启。后两种状态共用简化后的文案。
- 主题：日间 / 夜间，直接使用当前主题变量。
- “评审说明”提供空会话、保存失败示例和隐藏评审栏；`Alt+D` 恢复控制栏。
- 通用页默认滚动到新开关附近；语言、启动、新对话和窗口区段完整保留，可向上滚动查看。

交互稿只在本页内存中模拟保存，不连接 Core、不发送消息、不写入真实任务。
真实持久化、跨窗口同步、升级迁移与运行连续性仍须按主方案 R4 实施验证。

## 3. 通用设置

保持区段顺序：界面语言 → 启动后打开 → 新对话 → **会话** → 窗口。
“会话”组内先世界地图，再会话任务。使用现有标题、说明、右侧开关和分隔线，不新增卡片或设置分类。

| 项目 | 变更前 | 变更后 | 说明 |
| --- | --- | --- | --- |
| 会话组 | 只有“世界地图” | 下方增加“会话任务” | 两者都控制会话能力 |
| 标题 | 无 | `会话任务` | 区别于左栏“定时任务” |
| 说明 | 无 | `在所有会话中提供任务面板和队员任务工具；关闭不删除已有任务记录。` | 说明范围、作用和数据保留，不讲内部实现 |
| 默认状态 | 总是提供 Task | 未配置时关闭 | 新安装、升级缺省一致；已有任务不推导开启 |
| 保存 | 无该设置 | 点击即保存 | 不增加保存按钮、确认弹窗或重启要求 |

“所有会话”指当前连接的同一个 Host/Core 实例，不表示跨实例同步。

R2 将上一版设计稿的 `关闭后保留已有任务` 改为 `关闭不删除已有任务记录`，避免误解成“旧任务继续可用”。
这里只承诺关闭动作不删除数据库中的既有记录：关闭后旧任务同样不显示、不进入新动态输入，
任务工具、提醒与快捷键一起停用。已有 Task 的 get/list 与 create/update 同样不可用，
只返回当前能力不可用的局部结果；不提供只读旧任务的例外。重新开启后可再查看和管理原记录。
普通历史消息和已冻结输入遵循主方案 R4 的连续性规则；正在执行的工作不会因开关暂停或取消。
Run 的执行结果与 Task 记录的状态分开处理，关闭期间不会因 Run 完成而自动把 Task 改成已完成。

| 操作状态 | 开关与反馈 | 其他功能 |
| --- | --- | --- |
| 关闭 | 灰色，保留标题和说明 | 会话照常可用 |
| 开启 | 当前主题的黑白选中态 | 提供 Task 界面与工具 |
| 正在保存 | 仅锁本行开关，行下 `正在保存…` | 可切换页面，不等待执行结算 |
| 保存成功 | 应用返回值，清除临时反馈 | 不弹 Toast，不自动打开任务浮层 |
| 保存失败 | 保持上次保存值；行下 `未能保存，请重试。` + `重试` | 不影响消息或执行，不出现全页错误 |

忙时保存与普通保存相同。保存已成功后，局部投影刷新失败只重试读取，不能回滚开关或终止 Run。
原型失败按钮只模拟保存本身失败，不代表投影刷新失败。

## 4. 会话页

| 表面 | 变更前 | 关闭后 | 再开启 |
| --- | --- | --- | --- |
| 右上入口 | 执行 / 任务 N / 队员 N / 单聊 N | 执行 / 队员 N / 单聊 N | 执行 / 队员 N / 单聊 N / **任务 N**，任务固定最后 |
| 任务列表与详情 | 点击入口显示现有浮层 | 不挂载，不留空面板 | 使用原浮层，等用户主动打开 |
| 时间线任务卡 | 显示当前 Task 状态卡 | 不构建 Task 状态卡 | 按恢复后的投影呈现 |
| 普通消息 | 正文、回复、附件 | 全部保留，包括提到“任务”的历史文字 | 不变 |
| 执行 | 状态与过程入口 | 继续显示，开关不停止运行 | 不变 |
| 侧栏 | 项目、对话、使命板、定时任务 | 保持 | 不变 |
| 消息输入 | 输入框与草稿 | 保持，不改写或自动发送 | 不变 |

“任务面板”实际是现有浮层，不另造常驻侧栏。R3 将四项顺序统一为执行、队员、单聊、任务；
任务关闭时移除末项，不移动前三项。视觉顺序、DOM 焦点顺序和快捷键设置行顺序一致，不能只用 CSS order 调换。
当前详情组与单聊分别通过 Portal 挂到同一顶栏，实施时应让顶栏提供有序挂载位置，避免按 Portal 到达顺序排序。
手机仍沿用“对话 / 执行 + 更多”结构，更多菜单按队员、单聊、任务排列，关闭时移除任务；使命活动保持独立。
沿用现有右对齐规则，
不留占位控件，不显示“任务已关闭”、灰色任务按钮或“去设置开启”的引导条。

其他窗口关闭能力时，已打开的 Task 浮层应立即收起；焦点属于被删除区域时回到消息输入框，
否则保持当前有效焦点。正文与阅读位置按现有消息锚点恢复。
迟到请求、旧快捷键和旧通知链接不能重新打开浮层。任务编辑草稿不自动提交，普通消息草稿保留。
关闭动作不迁移、不批量完成、不取消任务。

以下文案在开启和关闭时完全相同，不维护双份配置；“当前界面”仅用于原型对照。

| 项目 | 变更前 | 变更后 | 说明 |
| --- | --- | --- | --- |
| 输入框提示 | `和队伍继续前行：补充线索、调整方向或布置新任务…` | `和队伍继续前行：补充线索或调整方向…` | 去掉 Task 功能教学，保留原有语气 |
| 空会话建议标题 | `整理成任务` | `梳理步骤` | 普通消息也能完成的动作 |
| 该建议填入的消息 | `把这次改动拆成可执行的任务，并标出需要我决策的部分。` | `把这次改动拆成可执行的步骤，并标出需要我决策的部分。` | 只填草稿，不创建替代对象 |

建议说明 `把目标拆分为负责人、顺序和验收点。` 保留。其他建议与输入交互保持现状。
以上是可见 UI 文案和用户可编辑的起步消息，不是新增 Bootstrap 或系统提示词。

## 5. 提醒页

现有页面叫 **提醒**，路径 **设置 → 提醒**。
[当前提醒规范](../ui/components/notification-center.md)明确生产界面没有 Notification Center 抽屉、
全局铃铛或 Inbox 未读总数。本稿还原现有提醒设置页，不增加这些入口。

| 项目 | 变更前 | 关闭后 | 再开启 |
| --- | --- | --- | --- |
| 标题与介绍 | 提醒；设置需要显示临时浮层的提醒。 | 保持 | 保持 |
| 应用内提醒总开关 | 一个总开关 | 保持，独立于任务能力开关 | 保持 |
| 会话组 | 待审批、提到你、本轮完成、单聊回复、执行未完成 | 全部保留 | 保持 |
| 使命组 | 使命需要你、使命状态变更与状态选择 | 全部保留 | 保持 |
| 任务组 | 任务状态变更、状态选择、已开启计数 | 整组不渲染，不留灰色占位或零计数 | 恢复原偏好与组件 |

宽屏仍为左侧会话、右侧使命，移除任务组后右下自然留白，不拉伸使命行或补解释卡片。
窄屏沿用生产 CSS 单列堆叠。任务能力开关不改写任何提醒偏好。

总开关说明在开启和关闭时共用：

| 变更前 | 变更后 | 说明 |
| --- | --- | --- |
| `正在查看的会话保持安静，包含它的使命和任务；重新开启提醒时不补弹旧消息。` | `正在查看的会话保持安静；重新开启提醒时不补弹旧消息。` | 去掉对象枚举，保留静默与不补弹规则 |

能力关闭时不再产生或展示 Task heads-up，正在显示的 Task heads-up 收起。
切换本身不是业务状态事件，重新开启不批量补弹历史提醒。
原型使用“已有用户开启任务提醒”的例子，便于验证隐藏后恢复原值；这不是修改提醒默认值。
主方案 R4 的历史 Inbox 读侧过滤是内部兼容要求，不据此增加 Inbox 界面。

## 6. 快捷键页与全部输入路径

本页继续复用真实 `ShortcutProvider`、`ShortcutSettings` 和原设置容器，不新增第二套设置页。
保留「通用 / 外观 / 快捷键 / 提醒」侧栏顺序、内容列、分组侧标题、键帽、录制与反馈样式。

R3 按最新要求替代 R2 的“保留旧四项键位”：本次升级统一重置四项键盘绑定，之后正常保存用户新设置。
`Mod` 仍代表平台主修饰键（macOS ⌘、Windows Ctrl），这里的“tab 4”是 `Mod+4`，不是 Tab 键加数字。

| 动作 | 变更前默认值 / 位置 | 本次升级后的默认值 / 位置 | Task 关闭后 |
| --- | --- | --- | --- |
| 执行 `execution` | Mod+1，第 1 项 | Mod+1，第 1 项 | 保持 |
| 队员 `members` | Mod+3，第 3 项 | Mod+2，第 2 项 | 保持 |
| 单聊 `dm` | Mod+4，第 4 项 | Mod+3，第 3 项 | 保持 |
| 任务 `tasks` | Mod+2，第 2 项 | **Mod+4，第 4 项** | 整行和动作停用，前三项不移动 |

### 一次性统一更新

推荐接受这次调整：默认关闭时得到连续的 1、2、3；开启仅追加第 4 项。
不判断四项旧值是否默认、自定义或未绑定，全部覆盖为新映射，不保留旧键位别名、不维护两套布局。
但“一次性”仍需要最小版本迁移，以免每次启动覆盖升级后的自定义配置。

建议复用已有 `shortcuts.json` 的 `schemaVersion`，从 1 升为 2，不另加应用版本标记或 Host 设置：

1. 无文件直接使用 v2 新默认值；有效 v1 只在 Main 的 `ShortcutPreferencesStore.load()` 标准化一次。
2. 四项键盘值直接设为 `execution=Mod+1`、`members=Mod+2`、`dm=Mod+3`、`tasks=Mod+4`，覆盖旧自定义和 null。
3. 若其余动作曾占用 Mod+1–4，将这些冲突绑定置为 null；只处理这四个组合，不重置其他非冲突键位。
   例如旧 `find=Mod+2`，升级后为 `find=null`、`members=Mod+2`，避免完整配置因重复组合被判无效。
4. 保留全部动作 ID、鼠标侧键映射和发送方式；“键位重置”不等于调用会清空全部配置的“恢复所有默认设置”。
5. 标准化结果与 `schemaVersion: 2` 一次原子写入同一文件；成功后再发布给窗口。v2 原样读取，不再重置。
   不使用每次 Main 启动归零的并发 `revision` 判断是否迁移，也不在开关事件或窗口初始化中执行重置。
6. 迁移写盘失败保留原文件，当前会话先用标准化后的内存配置，设置页用现有错误位提示
   `快捷键更新未保存，请重试。`；可重试或正常保存 v2，App 与会话继续可用。
   未成功写入时不得标记已迁移；下次读取仍是 v1 才重新尝试。损坏/未知格式沿现有 degraded 恢复路径处理。

四项旧绑定的差异处理可以删除；这个小迁移入口、完整配置唯一性校验和日后正常改绑的冲突处理仍需要保留。
原生侧键不属于本次数字键重置范围，但 Task 关闭时仍停用其动作。
更新说明只需一句“会话入口调整为执行、队员、单聊、任务，本次升级将这四项快捷键统一为 ⌘/Ctrl+1–4。”，
不增加确认弹窗或首次打开教学。

### 升级之后的开关与改绑

| 项目 | 变更前 | 关闭后 | 再开启 / 说明 |
| --- | --- | --- | --- |
| 设置行 | 始终显示“打开／收起任务” | 移除第 4 行及录制、清除、恢复入口 | 在单聊之后恢复，不显示灰色占位 |
| 默认与自定义键盘 | 匹配后打开或收起任务 | 不分发、不拦截 Task 按键，不弹错误 | 使用升级后最新保存的绑定，不重新重置 1–4 |
| 鼠标侧键 | 可绑定任务 | 不消费或转发该动作，覆盖抬起与 auxclick | 未被用户替换的原映射恢复 |
| 已存配置 | 一份本机配置 | 开关本身不清空绑定 | 不存第二份开关专用配置 |
| 关闭期间改绑任务组合 | Task 当前始终作为冲突对象 | 按用户新设置保存，并清空被替代的 Task 绑定；不提示已停用的 Task 冲突 | Task 为未绑定，不抢回、不产生重复组合 |
| 关闭期间改绑侧键 | 每个侧键指向一个动作 | 按用户选择改为新动作 | 不恢复被用户替换的映射 |
| 正在录制任务绑定 | 录制期间拦截输入 | 取消未提交候选、退出任务录制；其他动作录制不受影响 | 不提交消失的行；迟到回包不重开 |
| Tooltip / 菜单 / 旧回调 | 可发现或触发 Task | 不提供操作入口；执行回调检查当前能力 | 不能用旧事件重新打开面板 |

例如升级后 Task 关闭期间把 Mod+4 绑定给队员：保存为 `members=Mod+4`、`tasks=null`；
再开启仍是该配置。若未再改绑，开启后任务为 Mod+4、队员为 Mod+2。
这属于升级后的普通改绑，不是继续兼容旧版本的四项键位。
用户主动清除、单项恢复或恢复全部默认仍沿现有规则；与可用动作冲突时继续显示“替换并保存”。

### 控制位置

以 [Desktop Shortcuts v1](../contracts/desktop-shortcuts-v1.md) 为实现基线，保留一份本机配置及完整动作 ID 映射；
实施时升级该合同、`packages/contracts/src/shortcuts.ts` 类型、共享 parser/defaults 与 Main load，不能只改默认数组。
能力开关仍来自当前连接的 Host，不能把 `tasks` 从持久化 Schema 直接删掉：当前 parser 要求完整映射，
还要求组合唯一，否则会将既有配置判为无效。

| 层 | 建议控制方式 |
| --- | --- |
| 共享动作目录 | 按执行、队员、单聊、任务排列，默认值 1–4；增加按当前能力判断可用性的函数，不复制两套目录 |
| Main 配置加载 | v1 → v2 一次性统一四项、清除占位冲突并原子落盘；get/save 只向新 Renderer 提供 v2 |
| ShortcutSettings | 渲染/可录制候选/可见冲突只选可用动作；保存时仍处理完整配置，原子转移组合，保证唯一 |
| ShortcutProvider | 键盘匹配、dispatch、DOM 侧键按下/抬起/auxclick 共用可用性判断；不可用动作返回未处理 |
| ThreadWorkspace | 任务动作及实际打开入口再次读当前能力，避免旧注册与迟到事件绕过 |
| Main 原生侧键 | [shortcut-input.ts](../../apps/desktop/src/main/shortcut-input.ts) 也需识别当前窗口的有效动作；停用 Task 时不调用 preventDefault、不发送任务侧键事件 |
| 窗口能力同步 | 将当前 Host 连接代次下的 Task 可用性作为临时输入状态同步到 Main；不是第二份用户设置。连接切换或尚未确认时只停用 Task 动作，不阻断其他快捷键 |

只关闭 Renderer 回调仍不够：当前 `ShortcutProvider.finishMouse` 与 Windows Main `app-command`
会因为“配置里有绑定”而消费侧键，即使任务回调没有执行。两处都必须改看有效动作。
原型覆盖新顺序、升级后的默认值、设置行、Renderer 分发及普通改绑；“当前界面”使用旧顺序作比较。
原型不运行真实 v1 → v2 磁盘迁移；Main/IPC、实体侧键与多窗口留在实施验收。
Web 没有 Desktop 快捷键能力时，不为它新增该设置页；已有 Web 输入路径也不能打开关闭的 Task。

验收至少覆盖默认与自定义键、侧键两条平台路径、开关前已注册回调、任务录制中关闭、关闭期间改绑后再开启、
保留升级后绑定再开启，以及保存/恢复默认不产生重复组合或损坏完整配置。
新增迁移验收：旧默认/旧自定义/四项 null、其他动作占用 1–4、迁移写盘失败后恢复、v2 自定义重启不被覆盖、
窗口并发首次读取、切换 Host/Task 开关不重复迁移，以及 DOM Tab 顺序与视觉顺序相同。普通输入、复制粘贴、发送、执行、队员、
单聊和文件查找继续沿原有输入边界处理。

## 7. 原型与实施边界

| 项目 | 本次设计稿 | 实施阶段 |
| --- | --- | --- |
| 布局、日夜主题 | 复用四页生产组件与样式 | 接真实能力投影 |
| 保存与重试 | 本页内存模拟 | Core 持久化、真实失败和恢复 |
| Task 过滤 | 原型移除组件；用空数组适配当前 snapshot 组件 | 主方案 R4 要求关闭时省略 Task 投影及查询，不能用空数组代替“不提供”合同 |
| 执行连续性 | 固定运行态在切换后仍展示 | 真实 Run、队列、冻结输入、恢复回归 |
| 数据与提醒偏好 | 示例在重新开启后恢复 | 数据库、幂等、升级、多窗口、迟到请求与分页过滤 |
| 快捷键 | 新顺序和默认值、生产设置组件、Renderer 分发与内存保存 | 一次性配置迁移、Main 原生输入、完整持久化、窗口能力同步及跨平台验证 |
| Desktop / Web / 手机 | 本次桌面尺寸设计，复用共享组件 | 按 Host 能力边界分别验收 |

生产能力值来自当前连接的 Host，不得只依赖浏览器状态或 CSS 隐藏。
CLI、Bootstrap、动态上下文的逐项对照和数据规则仍见 [主方案 R4](task-capability-switch.md)。
